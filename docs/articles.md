# 記事の形と決まり

2026-10-04 にユーザーと決めた形 (「記事結構いい感じだからこの感じで固定したい」)。お手本は
`src/content/articles/nanikiru-1.mdx` (何切るの問題) と `modoshi-1.mdx` (読み物)。ひな形は `templates/`。
数字を出す台本はアプリのリポジトリの `scripts/articles/` (README に手順)。

## 決まり

- 数字はすべて、アプリと同じ評価エンジン (Rust) で読み切った値。どの記事にも、題の下に「この記事の期待値・和了率・平均打点は、
  アプリ「サンソー」の評価エンジンで計算しています」が自動で出る (記事ページの共通の部分)
- 問題は手牌とドラだけで出す。河は空 (見えている牌は手牌とドラ表示牌だけ) として計算する
- 巡目に左右されない局面を選ぶ (`turns.mts` で 1〜12巡目の最善と判定が変わらないこと)。問題に巡目は書かず、表の下の注に
  「序盤 (5巡目) で計算」と「どの巡目でも変わらない」を書く
- 「これが正解」の問題にするのは、最善が 2 番目よりはっきり上 (目安 3% 以上、◎ が 1 つ) の局面だけ。僅差 (◎ が 2 つ以上) の形は
  問題にせず、「こういう判断もある」という読み物にする
- 題・一覧の説明・URL・種類の札で答えを透かさない (札はページに出さない。URL は `nanikiru-<番号>` のように中立に)
- 表に載せる打牌は、巡目で判定が変わらないものだけ (3〜5 行)。最善・受け入れ最大・和了率最大など、話に出す打牌を選ぶ
- 理由は `breakdown.mts` の数字 (役が和了の何 % に付くか、平均打点の差の内訳) で言える範囲だけ書く。確かめていないことは書かない
- 文はです・ます。数は「2,212点」「26.1%」「13種42枚」、牌は「9萬」「3索」「東」と書く

## 何切るの問題の記事 (`templates/question.mdx`)

1. 題: 「この 1 向聴、何を切る？」のように答えが透けない形
2. 説明: 「ドラ 中 の親の手。受け入れの枚数と期待値で、どの牌を切るのが一番得かを比べます。」
3. 問題 (`question`): 場況「東場・親・ドラ 中」、ドラ表示牌、手牌 13 枚、ツモ牌、「3索をツモりました。何を切りますか？」。
   ページでは問題の後ろの本文が「答えを見る」でたたまれる
4. 本文: 「## 答え: X を切る」→ 表 → 注 → 「### 受け入れが一番多いのは …」「### 和了率が一番高いのは …」など、
   答えにならなかった打牌ごとの節 (切った形を小さい手牌の絵で) → 「## まとめ」(2 行)

## 読み物の記事 (`templates/reading.mdx`)

1. 題: 判断の形を言う「テンパイを取らない、という選択肢」
2. 一覧のカードと前後の記事に出す手牌 (`card`): 場況「東場・親・ドラ 2索」、本文の最初に出す手牌 13 枚、ツモ牌。問題の記事は
   `question` の手牌が出るので要らない
3. 本文: 場況と手牌の絵 → 「同じくらい有力でした」→ 表 (◎ が 2 つ) → 注 → 打牌ごとの節 → 「## どちらを選ぶか」(2 行)
